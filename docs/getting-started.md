# Getting Started — MyUNO Capital (Local Setup)

This guide takes you from a fresh clone to a fully running local instance of
**MyUNO Capital**, the Autonomous AI Operating System for solo entrepreneurs.

By the end you will have the Founder Console, the API, the database (Postgres +
pgvector), Redis, MinIO object storage, and a Celery worker all running locally
via Docker Compose.

---

## 1. Prerequisites

| Tool | Minimum version | Notes |
|------|-----------------|-------|
| Docker Engine | 24+ | `docker --version` |
| Docker Compose | v2 | `docker compose version` (note: the space — v2 plugin form) |
| Node.js | 20+ | Only needed for local-without-Docker frontend dev |
| Python | 3.12 | Only needed for local-without-Docker backend dev |
| make | any | Used for the convenience targets below |
| Git | any | To clone the repository |

You will also need:

- An **`ANTHROPIC_API_KEY`** — get one at <https://console.anthropic.com/>.
  This is required; the AI agents will not function without it.

---

## 2. Clone and configure

```bash
git clone https://github.com/your-org/MyUNO-Capital.git
cd MyUNO-Capital

# Create your local environment file from the template
cp .env.example .env
```

Open `.env` and fill in the values that matter for local development. At minimum:

- `ANTHROPIC_API_KEY` — your real Anthropic key.
- `SECRET_KEY` and `JWT_SECRET` — generate strong random strings, e.g.:

  ```bash
  python -c "import secrets; print(secrets.token_urlsafe(48))"
  ```

The database, Redis, and MinIO placeholders in `.env.example` already work
out of the box for local Docker development — you only need to change them if
you want different credentials. Integration keys (Stripe, GitHub, Google Ads,
SendGrid) can stay as placeholders until you wire up those features.

> **Tip:** `.env` is git-ignored. Never commit real secrets.

---

## 3. Start the stack

```bash
docker compose up -d
# or simply:
make up
```

This builds the images (first run only) and starts the following services:

| Service | Image / Build | Host port | Purpose |
|---------|---------------|-----------|---------|
| `frontend` | `./frontend` (Next.js 14) | **3000** | Founder Console (web UI) |
| `backend` | `./backend` (FastAPI) | **8000** | REST API + OpenAPI docs |
| `worker` | same image as `backend` | — | Celery worker for agent/background jobs |
| `postgres` | `pgvector/pgvector:pg16` | **5432** | Primary DB + vector memory |
| `redis` | `redis:7-alpine` | **6379** | Cache + Celery broker/result backend |
| `minio` | `minio/minio` | **9000** / **9001** | S3-compatible object storage / web console |

Check that everything is healthy:

```bash
docker compose ps
make logs        # tail logs from all services (Ctrl-C to stop)
```

---

## 4. Run database migrations

The schema is managed with Alembic. After the stack is up:

```bash
make migrate
# equivalent to:
# docker compose exec backend alembic upgrade head
```

This brings the database to the latest schema (`alembic upgrade head`),
including enabling the `pgvector` extension used for semantic memory.

---

## 5. Seed demo data

Load starter data (a demo tenant, example business templates, and sample
Decision Hub options):

```bash
make seed
# equivalent to:
# docker compose exec backend python -m app.scripts.seed
```

## 7. Common `make` targets

These wrap `docker compose` and keep commands consistent with the service
names above. Run `make help` to see them in your terminal.

| Target | What it does |
|--------|--------------|
| `make help` | Show all targets (default when you run `make`) |
| `make up` | Start all services in the background |
| `make down` | Stop services (keeps data/volumes) |
| `make build` | Build / rebuild all images |
| `make logs` | Tail logs from all services |
| `make migrate` | Apply DB migrations (`alembic upgrade head`) |
| `make makemigration m="msg"` | Generate a new autogenerated migration |
| `make seed` | Load seed/demo data |
| `make test` | Run backend (pytest) + frontend tests |
| `make lint` | Lint backend (ruff) + frontend (eslint) |
| `make format` | Format backend (black/ruff) + frontend (prettier) |
| `make shell` | Open a bash shell in the backend container |
| `make psql` | Open a `psql` session against the database |
| `make clean` | Stop services **and remove volumes** (destroys local data) |

## 8. Local development without Docker (optional)

If you prefer to run the backend and frontend directly on your host (e.g. for
faster iteration or debugging), you can still use Docker only for the
infrastructure services.

Start just the infrastructure:

```bash
docker compose up -d postgres redis minio
```

In `.env`, point the host-based processes at `localhost` instead of the Docker
service names:

```dotenv
POSTGRES_HOST=localhost
DATABASE_URL=postgresql+psycopg://myuno:change-me-postgres-password@localhost:5432/myuno_capital
REDIS_URL=redis://localhost:6379/0
CELERY_BROKER_URL=redis://localhost:6379/1
CELERY_RESULT_BACKEND=redis://localhost:6379/2
S3_ENDPOINT=http://localhost:9000
```

### Backend (FastAPI)

```bash
cd backend
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# Apply migrations against the dockerized Postgres
alembic upgrade head

# Run the API with autoreload
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

In a second terminal, run the Celery worker:

```bash
cd backend
source .venv/bin/activate
celery -A app.worker worker --loglevel=info
```

### Frontend (Next.js)

```bash
cd frontend
npm install
npm run dev      # serves on http://localhost:3000
```

## 9. Troubleshooting

### Port already in use
If `docker compose up` fails with a "port is already allocated" error, another
process is using 3000, 8000, 5432, 6379, 9000, or 9001. Either stop that
process, or change the host port in `.env` (e.g. `FRONTEND_PORT`,
`BACKEND_PORT`) and restart with `make up`.

### `pgvector` extension errors
The `pgvector/pgvector:pg16` image ships the extension binary, but it must be
enabled in the database. This happens automatically in the initial migration
(`CREATE EXTENSION IF NOT EXISTS vector;`). If you see
`type "vector" does not exist`, you likely skipped migrations — run
`make migrate`. If you are using an external/managed Postgres, make sure the
`vector` extension is available and enabled there.

### Missing or invalid `ANTHROPIC_API_KEY`
Agent endpoints will return auth/configuration errors if the key is missing.
Confirm it is set:

```bash
docker compose exec backend printenv ANTHROPIC_API_KEY
```

After changing `.env`, recreate the affected containers so they pick up the
new values:

```bash
docker compose up -d --force-recreate backend worker
```

### Resetting volumes / starting fresh
To wipe all local data (database, Redis, MinIO objects) and start clean:

```bash
make clean        # docker compose down -v  (removes named volumes)
make up
make migrate
make seed
```

### Services keep restarting
Check logs for the failing service:

```bash
docker compose logs backend
docker compose logs worker
```

A common cause is the backend starting before Postgres is ready — the compose
file uses healthchecks and `depends_on` to prevent this, but if you edited
those, restore the `condition: service_healthy` dependencies.
